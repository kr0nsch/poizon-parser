# poizon-parser — обувь с thepoizon.ru в вашем размере

[![CI](https://github.com/kr0nsch/poizon-parser/actions/workflows/ci.yml/badge.svg)](https://github.com/kr0nsch/poizon-parser/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Python 3.9+](https://img.shields.io/badge/python-3.9%2B-blue.svg)](https://www.python.org/)

Вводите длину стопы в сантиметрах — получаете обувь выбранного бренда, которая
**есть в наличии именно в вашем размере**, с ценой за этот размер, сроком
доставки и фото. Размер переводится по официальным таблицам Nike, Adidas,
New Balance, ASICS, Reebok и Puma, для остальных брендов — по общей сетке.

**In English.** poizon-parser is an unofficial command-line tool and local web
app for thepoizon.ru. You enter your foot length in centimetres (or a size in
EU, UK or US); the tool converts it with the manufacturer's official size chart
where one is available (Nike, Adidas, New Balance, ASICS, Reebok, Puma) or with
a generic chart otherwise, matches the result against the RU/EU size
labels POIZON puts on every item and lists the shoes that are in stock in that
exact size, with the price for that size. The backend uses only the Python 3.9+
standard library; the optional web UI is built with React and Vite. The rest of
this document is in Russian.

> [!IMPORTANT]
> **Неофициальный проект.** Инструмент не связан с POIZON / Dewu, не одобрен
> и не поддерживается ими. Он читает только общедоступные страницы сайта — без
> входа в аккаунт, корзины и заказов — и предназначен для личного
> использования. Соблюдайте условия использования thepoizon.ru и держите темп
> запросов вежливым: не уменьшайте паузу между запросами без нужды и не
> запускайте много копий одновременно.

## Быстрый старт

Нужен **Python 3.9+**. Бэкенд использует только стандартную библиотеку —
устанавливать пакеты не нужно. **Node.js 22.13+ или 24+** и **pnpm**
понадобятся только для сборки и разработки веб-интерфейса.

```bash
git clone https://github.com/kr0nsch/poizon-parser.git
cd poizon-parser
```

На macOS и Linux вместо `python` может понадобиться `python3`.

### Веб-интерфейс

Соберите интерфейс один раз и запустите сервер:

```bash
cd frontend
pnpm install
pnpm build
cd ..
python main.py web
```

В браузере откроется `http://127.0.0.1:8765/`. Сервер сам раздаёт сборку из
`frontend/dist`, отдельный Node.js-процесс не нужен. Если сборки нет, он
отдаёт запасную страницу `web/index.html`, поэтому `python main.py web`
работает и без Node.js. Подробнее — в разделе
[Веб-интерфейс и API](#веб-интерфейс-и-api).

### CLI

```bash
python main.py size 26,5 -b nike       # какой это размер у Nike и других брендов (без сети)
python main.py shoes -b nike -s 26,5   # что есть в наличии в этом размере
python main.py allbrands -s 26,5       # то же сразу по всем брендам с официальной таблицей
python main.py --help                  # список команд
```

Калькулятор `size` работает по встроенным таблицам и к сайту не обращается:

```text
Длина стопы 26,5 см · мужская сетка

Nike (≈ ближайший):
  EU 43  ·  US 9,5  ·  UK 8,5  ·  стопа 26,7 см  ·  CM/JP 27,5 см

Сравнение брендов:
  Бренд         EU       US    UK    стопа    CM/JP
  Nike          43       9,5   8,5   26,7     27,5
  Adidas        43⅓      9,5   9     26,7     27,5
  New Balance   42       8,5   8     26,5     —
  ASICS         42       8,5   7,5   26,5     —
  Reebok        42,5     9,5   8,5   26,7     —

Одна стопа — разные EU: сетки брендов не совпадают, это нормально.
Нет в сравнении: Puma (не публикует длину стопы)
```

Так выглядит выдача `shoes -b nike -s 26,5`: формат настоящий, а модели, цены и
SPU условные. Под таблицей ещё печатается нумерованный список ссылок на
карточки.

```text
#  Модель                                        Размер на POIZON  Посадка  Цена        Доставка    SPU
─  ────────────────────────────────────────────  ────────────────  ───────  ──────────  ──────────  ────
1  Nike Dunk Low Retro Низкие кроссовки Чёрно-…  RU 42 / EU 43     -0,5     ≈ 8 790 ₽   21-25 дней  1002
2  Nike Air Force 1 '07 Низкие кроссовки Белые   RU 42 / EU 43     —        ≈ 10 450 ₽  3-5 дней    1001
3  Nike Pegasus 41 Беговые кроссовки Серые       RU 42 / EU 43     —        ≈ 11 200 ₽  7-10 дней   1003

В наличии: 3 модели · от 8 790 ₽ до 11 200 ₽
Запрошено: 26,5 CM → EU 43
«≈» у 3 из 3: точного перевода из CM в таблице модели нет, взят ближайший размер — сверьте по ссылке.
Примечание: по официальной таблице Nike (мужская сетка), ближайшая длина стопы 26,7 см
Колонка «Посадка» — рекомендация сайта: на сколько сместить размер.
```

- **«Размер на POIZON»** — полный ярлык, под которым размер лежит на сайте:
  по нему удобно сверяться с карточкой.
- **«≈» перед ценой** относится к переводу размера, а не к цене: 26,5 см нет в
  таблице Nike, поэтому взята ближайшая строка — стопа 26,7 см, EU 43.
- **«Посадка»** — совет сайта для модели; `-0,5` значит «модель большемерит,
  берите на полразмера меньше». Парсер его только показывает.

## Команды CLI

| Команда | Что делает | Обращается к сайту |
|---------|------------|--------------------|
| `web` | локальный веб-интерфейс | да |
| `shoes` | обувь бренда в вашем размере — основной сценарий | да |
| `allbrands` | то же сразу по всем брендам с официальной таблицей | да |
| `size` | калькулятор: длина стопы → размеры брендов | нет |
| `brandchart` | официальная размерная таблица бренда | нет |
| `brands` | список брендов сайта | да |
| `chart` | таблица размеров конкретной модели с сайта | да |
| `find` | поиск по названию с отбором по размеру | да |
| `sizes` | все размеры и цены одной модели | да |
| `search` | поиск моделей по названию без разбора размеров | да |

Справка по любой команде: `python main.py <команда> --help`.

### Общие флаги

Их можно писать и до, и после имени команды:
`python main.py --quiet shoes -b nike -s 26,5` и
`python main.py shoes -b nike -s 26,5 --quiet` равнозначны.

| Флаг | По умолчанию | Что делает |
|------|--------------|------------|
| `--delay` | `0.7` | пауза между запросами, с — задаёт темп общего ограничителя |
| `--timeout` | `30` | таймаут одного запроса, с |
| `-v, --verbose` | — | печатать лог запросов клиента |
| `--quiet` | — | не печатать прогресс |
| `--no-cache` | — | не использовать дисковый кэш страниц |
| `--cache-ttl` | `900` | срок жизни кэша, с |
| `--version` | — | версия программы (только перед командой) |

Команда `web` эти флаги принимает, но не применяет: темп запросов там
выбирается в интерфейсе, а кэш работает всегда.

Результат печатается в stdout, прогресс и ошибки — в stderr, так что вывод
можно перенаправлять в файл. Коды выхода: `0` — есть результат; `1` — ничего
не найдено (у `chart` и `brandchart` — нет таблицы); `2` — ошибка ввода, сети
или записи; `130` — прервано Ctrl+C.

### `shoes` — бренд + длина стопы → что в наличии

```bash
python main.py shoes -b nike -s 26,5
python main.py shoes -b "new balance" -s 25,5 --gender women
python main.py shoes -b adidas -s 26,2 --max-price 9000
python main.py shoes -b asics -s 26,5 --check 60 -f csv -o asics.csv
python main.py shoes -b nike -s 26,5 --check 0       # весь каталог бренда
python main.py shoes -b nike -s 42 --scale EU        # если знаете размер в EU
python main.py shoes -b adidas -s "US M 9"           # шкала прямо в размере
python main.py shoes -b nike -s 26,5 -f html         # HTML-отчёт в result/
```

| Флаг | По умолчанию | Что делает |
|------|--------------|------------|
| `-b, --brand` | — | бренд как на сайте: `nike`, `adidas`, `"New Balance"` (обязателен) |
| `-s, --size` | — | длина стопы в см, `15–40`, например `26,5`; можно со шкалой или единицей: `"EU 43"`, `"26,5 см"` (обязателен) |
| `--scale` | `CM` | шкала размера: `CM`, `MM`, `EU`, `RU`, `UK`, `"US M"`, `"US W"` |
| `--gender` | `men` | сетка бренда: `men` (мужская / унисекс) или `women` |
| `-n, --limit` | `20` | сколько моделей вывести |
| `--check` | `40` | сколько карточек проверить; `0` — весь каталог |
| `--tolerance` | `0` | допуск при сравнении с EU-ярлыком: `0.5` захватит соседний полуразмер |
| `--max-price`, `--min-price` | — | фильтр по цене вашего размера, ₽ |
| `--kids` | — | добавить детскую обувь |
| `-w, --workers` | `3` | параллельных загрузок карточек (темп запросов при этом не растёт) |
| `-f, --format` | `table` | `table`, `json`, `csv` или `html` |
| `--embed-images` | — | вшить фото в HTML-отчёт |
| `-o, --out` | — | сохранить в файл; для `-f html` — папка отчёта (по умолчанию `result/`) |

Ищется только обувь: одежда, сумки и аксессуары бренда отбрасываются по
категории сайта. В выдачу попадают лишь размеры, доступные к заказу, она
отсортирована по цене. Бренд ищется по названию или слагу; при частичном
совпадении берётся самое короткое имя (`nike` не превратится в
«Nike Sportswear»), а при опечатке CLI подскажет похожие бренды.

### `allbrands` — один замер, все бренды с официальной таблицей

Тот же сценарий без выбора бренда: замер прогоняется по всем брендам с
официальной сеткой, и каждому размер переводится по **его** таблице.

```bash
python main.py allbrands -s 26,5
python main.py allbrands -s 25 --gender women --max-price 12000
python main.py allbrands -s 9 --scale "US M" --brands puma reebok
python main.py allbrands -s 26,2 --check 0 --total 30 -f html
```

| Флаг | По умолчанию | Что делает |
|------|--------------|------------|
| `-s, --size`, `--scale`, `--gender` | `CM`, `men` | как у `shoes` |
| `--brands` | все | ограничить список: `--brands nike reebok`; понимает `nb`, `jordan`, `"adidas originals"` |
| `-n, --limit` | `10` | сколько моделей брать **у одного бренда** |
| `--total` | `0` | общий потолок выдачи после сортировки по цене; `0` — без ограничения |
| `--check` | `40` | сколько карточек проверять у бренда; `0` — весь каталог |
| `--tolerance`, `--max-price`, `--min-price`, `--kids`, `-w`, `-f`, `--embed-images`, `-o` | | как у `shoes` |

Над таблицей печатается сводка «По брендам»: сколько моделей нашлось у каждого
и в какой EU перевёлся замер. Разные EU в одной выдаче — норма, это разные
официальные сетки; в таблицу добавляется колонка «Бренд». По длине стопы Puma
пропускается (замер стопы она не публикует) и перечисляется отдельной строкой;
с `--scale EU`, `UK`, `"US M"` или `"US W"` она участвует. `RU` здесь не
подходит: в таблицах производителей его нет. Бренд, в официальную таблицу
которого размер не входит, пропускается с пометкой в прогрессе ещё до сбора
его каталога. Неизвестный бренд в `--brands` или размер вне таблиц всех выбранных
брендов — ошибка ещё до обращения к сайту.

### `size` — калькулятор по длине стопы

```bash
python main.py size 26,5
python main.py size 26,5 -b nike
python main.py size 24 -b asics --gender women
```

Показывает размер выбранного бренда (EU, US, UK, длина стопы и ярлык CM/JP,
если он отличается) и сравнение всех брендов, у которых есть колонка длины
стопы. «(≈ ближайший)» — точного значения в таблице нет. В конце перечислены
бренды, не попавшие в сравнение, и почему. Пример вывода — в
[быстром старте](#cli). Работает без сети.


### `chart` — таблица размеров модели

```bash
python main.py chart <spuId или ссылка на товар>
python main.py chart <spuId> -f json
```

Выводит опорные строки таблицы размеров из карточки POIZON и ярлыки размеров
в наличии с ценой (начало вывода — название и ссылка — опущено, данные
условные):

```text
Официальная таблица (опорные строки с сайта):
  EU 35,5 · RU 34,5 · UK 3 · US M 3,5 · US W 5 · CM 22,5
  EU 36 · RU 35 · UK 3,5 · US M 4 · US W 5,5 · CM 23
  EU 36,5 · RU 35,5 · UK 4 · US M 4,5 · US W 6 · CM 23,5

Размеры в наличии (ярлыки POIZON):
  RU 41,5 / EU 42,5      9 890 ₽
  RU 42 / EU 43          10 450 ₽
```

`-f json` отдаёт те же строки таблицы и предложения в наличии (с вариантом и
`sku_id`). Если таблицы у модели нет, код выхода `1`.

### `find` — поиск по названию с отбором по размеру

```bash
python main.py find -q "new balance 530" -s 42 --scale EU
python main.py find -q "adidas samba" -s "RU 42,5"
python main.py find -q "nike dunk" -s 43 --max-price 9000 -n 5
python main.py find -q "asics gel" -s 42 -f json -o result.json
```

| Флаг | По умолчанию | Что делает |
|------|--------------|------------|
| `-q, --query` | — | что искать: `"nike air force 1"` (обязателен) |
| `-s, --size` | — | размер: `42`, `42,5`, `"42 2/3"`, `"EU 43"`, `RU41` (обязателен) |
| `--scale` | — | шкала на POIZON: только `RU` или `EU`, регистр не важен |
| `--strict-scale` | — | не искать размер в других шкалах, если в основной его нет |
| `-n, --limit` | `10` | сколько моделей вернуть |
| `--check` | `limit × 3`, не меньше 10 | сколько карточек из выдачи поиска проверить (не больше 100 — это одна страница поиска) |
| `--tolerance` | `0` | допуск по размеру |
| `--max-price`, `--min-price` | — | фильтр по цене **найденного** размера |
| `--include-unavailable` | — | показывать и размеры, которых нет в наличии |
| `-f, --format` | `table` | `table`, `json` или `csv` |
| `-o, --out` | — | сохранить в файл |

`find` не переводит размер, а сравнивает его прямо с ярлыками SKU (RU/EU),
поэтому US, UK и сантиметры здесь не принимаются — для них есть `shoes`.
Как выбирается шкала — в разделе [Поиск по названию](#поиск-по-названию-find).

### `web` — локальный сервер

```bash
python main.py web
python main.py web --port 8080 --no-open
python main.py web --host 0.0.0.0        # доступ из локальной сети
```

| Флаг | По умолчанию | Что делает |
|------|--------------|------------|
| `--host` | `127.0.0.1` | адрес, на котором слушает сервер |
| `--port` | `8765` | порт; если он занят, CLI подскажет другой |
| `--no-open` | — | не открывать браузер |

### Форматы вывода

- `table` — таблица для чтения в консоли.
- `json` — список результатов: модель (`title`, `brand`, `article`, `spu_id`,
  `url`, `image`), запрос и перевод (`requested_size`, `requested_scale`,
  `converted_eu`, `converted_foot`, `converted_cm`, `exact_conversion`,
  `conversion_note`), найденный размер (`sizes`, `matched_scale`, `size`,
  `variant`, `sku_id`), цена и наличие (`price`, `price_text`, `in_stock`,
  `delivery`) и совет по посадке (`size_tip`).
- `csv` — колонки `title, brand, article, requested_size, matched_scale, size,
  price, currency, in_stock, delivery, spu_id, sku_id, url`.
- `html` — самодостаточный отчёт (только `shoes` и `allbrands`), см.
  [HTML-отчёты](#html-отчёты).

С `-o` результат пишется в файл. CSV сохраняется с BOM, чтобы Excel узнал
UTF-8; JSON и таблица — без BOM. Путь из `-o` проверяется до обхода сайта, а
если файл всё же не удалось записать в конце, результат печатается в консоль,
чтобы долгий обход не пропал.

## Как подбирается размер

### Две ловушки наивного подбора

**1. Размер «42» на POIZON — это не 42 производителя.** Сайт подписывает
каждый товар двумя шкалами, и его «RU» равен EU минус единица. Если вы носите
Nike EU 42, на POIZON эта пара лежит под ярлыком **«RU 41 / EU 42»** — выбрав
там «RU 42», вы получите обувь на размер больше. Поэтому размер задаётся длиной
стопы, а в выдаче всегда показан полный ярлык POIZON.

**2. Цена привязана к размеру, а не к модели.** Каждый размер выставляют разные
продавцы. В примере выше у New Balance 530 EU 42 стоит 7 050 ₽, EU 45,5 —
19 490 ₽, а узкая полнота EU 42,5 — 17 251 ₽ против 7 650 ₽ за стандартную.
«Цена от» на карточке — минимум по всем размерам и к вашему размеру обычно
отношения не имеет. Парсер берёт цену конкретного размера.

### От замера стопы к паре в наличии

```text
длина стопы, см
      ↓  официальная таблица бренда, мужская или женская сетка
EU-размер этого бренда
      ↓  сравнение с ярлыками SKU на POIZON (RU / EU)
конкретная пара в наличии + цена этого размера
```

**Как мерить.** Встаньте на лист бумаги пяткой к стене, отметьте самый дальний
палец и измерьте расстояние от края листа до отметки. Мерьте вечером и обе
ноги, берите большее значение. Запас на посадку уже заложен в таблицах
производителей — прибавлять ничего не нужно.

Длина стопы принимается в пределах 15–40 см — и в CLI (`shoes`, `allbrands`,
`size`), и в вебе. Число вне этих границ — ошибка. У `shoes` и `allbrands` она
ещё и подсказывает, что «43» скорее всего размер EU (`--scale EU`), а «265» —
миллиметры (`--scale MM`); если шкала написана прямо в `-s` (`"CM 43"`),
подсказка предлагает переписать сам размер (`"EU 43"`), а не добавить
`--scale`. `size` и веб просто называют допустимые границы. Если точного
значения в таблице бренда нет, берётся ближайшая строка с длиной стопы **не
меньше** замера, то есть размер округляется вверх, а перевод помечается «≈».

### Длина стопы и ярлык CM/JP — разные величины

Главный подвох, из-за которого наивный перевод ошибается на размер:

| Nike, US M 9 | |
|---|---|
| ярлык размера «CM / JP» | **27,0 см** |
| реальный замер стопы «Foot Length» | **26,2 см** |

Парсер ищет по **замеру**, а в карточке отдельно показывает «стопа 26,2 см» и,
когда величины различаются, «CM/JP 27 см» — по ярлыку удобно сверяться с
POIZON.

- **Nike и Adidas** публикуют обе колонки, перевод идёт напрямую по замеру.
- **New Balance** публикует `Length (cm)`, а официальная страница **ASICS**
  предлагает сопоставлять замер от пятки до пальца со своей колонкой CM — эти
  ряды используются как длина стопы.
- **Reebok** даёт замер «Heel-Toe» только в дюймах; в сантиметры он переводится
  в генераторе таблиц.
- **Puma** замер стопы не публикует нигде — только ярлык JPN/CM, который у
  всех брендов больше реальной стопы (у Nike и Adidas ярлык «27 см» стоит на
  паре под замер 26,2–26,3 см). Поэтому колонки длины стопы у Puma нет: по
  замеру она подбирается по общей сетке стопы (см. ниже) с пометкой «≈», не
  участвует в `allbrands` по сантиметрам и не показывается в веб-фильтре
  «официальные бренды». Её официальная таблица работает для US, UK и EU.

Колонки одного бренда никогда не подставляются другому. Поэтому одна и та же
стопа даёт разные обозначения: 26,5 см — это Nike EU 43, Adidas EU 43⅓,
Reebok EU 42,5, а у New Balance и ASICS точно EU 42 (см. вывод `size` в
[быстром старте](#cli)).

**Общая сетка стопы** нужна, когда своей колонки длины стопы у бренда нет:
Puma, бренды без официальной таблицы (Vans, Converse…) и веб-поиск по ним
(интерфейс всегда шлёт длину стопы). Для замера берётся EU каждой официальной
колонки длины стопы (Nike, Adidas, New Balance, ASICS, Reebok) в выбранной
мужской или женской сетке, а итог — их медиана там, где замер покрывают хотя
бы три таблицы. Сетка сглажена, чтобы EU не убывал с ростом стопы, а за её
краями размер оценивается шагом ⅔ см на EU. Перевод всегда помечается «≈»:
26,5 см у Puma или Vans — это ≈ EU 42,5. Колонка «Длина стопы» из карточки
товара с замером не сравнивается — в ней ярлыки, а не замер.

### Шкалы и порядок перевода

В SKU сайт публикует только две шкалы — **RU и EU**, причём RU = EU − 1. Шкал
US, UK и CM в карточках нет, поэтому `shoes` и `allbrands` переводят ввод в EU.

Шкала ввода (`--scale`, регистр не важен): `CM` — длина стопы, по умолчанию;
`MM` — она же в миллиметрах (границы те же, 150–400 мм); `EU`, `RU`, `UK`,
`"US M"`, `"US W"`. Понимаются и варианты написания: `us m`, `usw`, `см`,
`евро`, `"US Женские"`. Шкалу можно указать прямо в значении — `"EU 43"`,
`"US W 7"`, `"usm 9"`, `"UK 8"`, `"CM 26,5"`, `"СМ 26,5"`, `"MM 265"`,
`"ММ 265"`, `"US Женские 7"`: она главнее `--scale`. Исключение — голое «US»:
пол оно не задаёт и явно выбранную `"US M"` или `"US W"` не перебивает.

Размер в `shoes`, `allbrands` и `find` разбирается строго, целиком. Понимаются
дроби (`"42 2/3"`, `"EU 42 2/3"`, `"US 9 1/2"`), пол после голого US
(`"US 7W"`, `"US 7 W"`, `"US 9 муж"`) и единица в конце: `"26,5 см"` и
`"265 мм"` — это CM и MM, и они, как и шкала впереди, главнее `--scale`.
Любой другой хвост после числа — ошибка (`"42-43"`, `"42 EU"`, `"7W"`), как и
две шкалы сразу (`"EU 42 см"`).

Перевод в EU — от самого достоверного источника к запасному:

1. **Официальная таблица бренда** (Nike, Adidas, New Balance, ASICS, Reebok,
   Puma), если бренд публикует запрошенную шкалу. Если US, UK или длина стопы
   не входят в его таблицу (выходят за её пределы или попадают в пропуск
   сетки, как US M 15,5 у Adidas), такого размера у бренда нет: `shoes` и
   веб-поиск сразу завершаются ошибкой с названием таблицы, не собирая
   каталог, а `allbrands` пропускает такой бренд.
2. Длина стопы без своей колонки у бренда — [общая сетка стопы](#длина-стопы-и-ярлык-cmjp--разные-величины).
   Дальше по списку идут только US и UK; EU не переводится, а RU берётся по
   строке таблицы товара или как EU − 1.
3. Таблица самого товара из карточки POIZON (`sizeAssistantModule`, три опорные
   строки).
4. Встроенная эталонная атлетическая сетка на весь диапазон (с поправкой под
   бренд по опорным строкам товара).
5. Типовое смещение.

Всё, что переведено не из точной строки таблицы, помечается «≈», и к EU-ярлыку
тогда допускается ближайший размер в пределах трети (у Adidas шаг сетки ⅓).
Рядом всегда стоит ярлык POIZON — сверьте его по ссылке перед заказом. Если вы
точно знаете свой размер в EU, укажите его: переводить не придётся.

**«US» без уточнения — мужская шкала.** В кроссовочном контексте «US» означает
US M. Женская шкала (`US W`) для той же пары примерно на 1,5 размера больше:
US W 5 и US M 3,5 — одна и та же обувь (EU 35,5). Поэтому «13» переводится
по-разному: `US W` всегда идёт по женской сетке бренда, `US M` — по мужской, а
`UK`, `EU` и `CM` — по сетке, выбранной `--gender` (по умолчанию мужской, как в
таблице):

| Ввод | Как понято | Nike | Adidas | NB | ASICS | Reebok | Puma |
|------|-----------|------|--------|-----|-------|--------|------|
| `13` + `US M` (или `US`) | мужской 13 | EU 47,5 | EU 48 | EU 47,5 | EU 48 | EU 47 | EU 47 |
| `13` + `US W` | женский 13 | EU 45,5 | EU 46⅔ | EU 45,5 | EU 46 | EU 45 | вне таблицы |
| `13` + `UK` | UK 13 | EU 48,5 | EU 48⅔ | EU 48,5 | EU 49 | EU 48,5 | EU 48,5 |
| `13` + `EU` | EU 13 — не бывает | ничего не найдётся | | | | | |

### Поиск по названию (`find`)

У `find` логика другая: размер не переводится, а сравнивается прямо с ярлыками
SKU.

1. Если указан `--scale` (`RU` или `EU`) или шкала в самом размере, ищем только
   в ней.
2. Иначе берём шкалу, которую сайт показывает для модели по умолчанию (обычно
   RU), — «42» без шкалы чаще всего означает RU 42, то есть EU 43.
3. Если в ней такого размера нет, переходим к следующей шкале и явно пишем в
   выводе, где нашли (`42,5 EU`). Переход отключается `--strict-scale`.

Шкалы внутри одного сравнения не смешиваются: выбирать «где дешевле» между
RU 42 и EU 42 нельзя — это обувь разной длины. Если в итоговой таблице всё же
оказались разные шкалы, парсер предупредит отдельной строкой. Дробные размеры
вида `42⅓`, `41⅔`, `34½` разбираются корректно и не приравниваются к целым.

### Как хранятся и обновляются

Официальные строки вручную сверены и записаны прямо в
`tools/build_size_charts.py`. Генератор собирает из них
`poizon_parser/data/size_charts.json` (файл генерируемый — руками его не
правят). Он не использует сеть, локальный Excel или HTML-кэш, поэтому
повторный запуск всегда даёт тот же файл, и перед записью проверяет состав
брендов, число строк, сортировку EU и длины стопы, полноту колонки длины стопы,
HTTPS-источник и дату сверки.

```bash
python tools/build_size_charts.py          # пересобрать JSON
python tools/build_size_charts.py --check  # только проверить, что JSON актуален (так делает CI)
```

У каждой строки таблицы есть поля `us`, `uk`, `eu`, `cm` (колонка CM/JP/Length
производителя) и `foot` (значение, с которым официальный источник предлагает
сопоставлять замер стопы). У Nike и Adidas `cm` и `foot` различаются, у
New Balance и ASICS совпадают, у Reebok есть только `foot`, у Puma — только
`cm`. В JSON попадают также ссылки на мужской и женский источники и дата
сверки, своя у каждого бренда. Чтобы обновить таблицу, поправьте значения и
дату в `VERIFIED_AT` (при изменении числа строк — и `EXPECTED_ROWS`),
пересоберите JSON и запустите тесты.

Если бренд какую-то шкалу не публикует, перевод честно уходит на общую сетку, а
не берётся у соседа. Для брендов **без** официальной таблицы (Vans,
Converse…) длина стопы переводится по
[общей сетке стопы](#длина-стопы-и-ярлык-cmjp--разные-величины), а US и UK — по
таблице товара или эталонной атлетической сетке. Пометки «≈» нет, только когда
US или UK точно совпали со строкой таблицы товара.

## Блокировки, лимиты и капча

Главный приём — **делать меньше запросов и держать ровный темп**, а не
обманывать защиту.

| Приём | Что даёт |
|-------|----------|
| **Ограничитель частоты** (token bucket, общий на все потоки) | сколько бы потоков ни работало, темп не превысит заданный (`--delay`, в вебе — «Темп запросов») |
| **Параллельная загрузка** (`-w`, по умолчанию 3) | перекрывает сетевые задержки, **не повышая** частоту запросов |
| **Предфильтр по цене** | если минимальная цена модели в листинге уже выше `--max-price`, её карточка не загружается вовсе |
| **Дисковый кэш HTML** | повторный прогон, например с другим размером, берёт страницы из кэша (15 минут по умолчанию) |
| **Пережидание 429 / 403** | до трёх автоматических пауз: по `Retry-After`, но не дольше 90 с, иначе 15, 30 и 45 с; пауза общая для всех потоков |
| **Адаптивное замедление** | после каждого 429/403 и каждой проверки пауза между запросами растёт на 1 с (до +4 с) и понемногу спадает после успешных загрузок |
| **Повторы** | при сетевых ошибках и ответах 5xx — до трёх попыток с нарастающей задержкой |
| **Порционный обход** | карточки грузятся порциями, поэтому лимит выдачи и «Стоп» срабатывают сразу, а не после очереди из тысяч заданий |

Кэш личный для пользователя и общий для CLI и веб-сервера: на Windows —
`%LOCALAPPDATA%\poizon-parser\cache`, на Linux и macOS —
`$XDG_CACHE_HOME/poizon-parser` или `~/.cache/poizon-parser`
(`poizon_parser.client.default_cache_dir()` возвращает этот путь). Заглушки и
страницы проверки в него не попадают. На Linux и macOS папку кэша, которая
принадлежит другому пользователю или открыта всем на запись, парсер
игнорирует и работает без кэша.

В вебе темп выбирается в форме:

| Темп | Пауза между запросами | Потоков |
|------|-----------------------|---------|
| Бережный | 1,2 с | 1 |
| Обычный | 0,6 с | 3 |
| Быстрый · риск лимита | 0,35 с | 5 |

Под прогрессом в вебе по ходу поиска обновляется статистика: запросов к сайту,
взято из кэша, отсеяно по цене, пауз из-за лимита.

Чего парсер **не** делает: не решает капчи, не крутит прокси и не подменяет
отпечаток браузера. Вместо этого он ведёт себя как вежливый клиент и
останавливается, когда сайт просит.

### Капча и ручная пауза

Если после автоматических пауз сайт продолжает отвечать 429/403 или вместо
страницы показывает проверку, парсер не падает, а встаёт на паузу.
Одноразовую заглушку с cookie `C3VK` он проходит сам, без участия человека.

- **В вебе** появляется баннер «Сайт просит пройти проверку» с кнопками
  «Открыть проверку» (новая вкладка, поиск не теряется), «Продолжить» и
  «Отменить». Найденное и прогресс сохраняются, поиск продолжается с того же
  места. Кнопкой **«Пауза / пройти проверку»** можно остановиться и самому —
  например, если проверку не распознало автоматическое определение: потоки
  встают перед следующим запросом (уже идущие запросы завершаются, ожидание
  лимита прерывается), а пока пауза не наступила, её можно отменить.
- **В терминале** — у команд, которые загружают страницы сайта (`shoes`,
  `allbrands`, `brands`, `sizes`, `chart` и `find`, пока он проверяет
  карточки), — парсер печатает ссылку и ждёт: пройдите проверку в браузере и
  нажмите Enter, или введите `q` и Enter, чтобы прервать. Вопрос один на все
  потоки: один Enter отпускает всех, а после отказа следующие проверки
  прерывают работу без нового вопроса. Пауза бывает, только если стандартный
  ввод — интерактивный терминал; при запуске из скрипта, планировщика или CI
  команда не ждёт ввода и завершается с сообщением о проверке. Блокировка
  поискового API (`search` и первый шаг `find`) не ждёт: команда сразу
  завершается с ошибкой.
- Если обход прерван проверкой, `shoes`, `allbrands` и `find` выводят то, что
  успели найти до неё, помечают выдачу как неполную и завершаются с кодом `2`.

Важный нюанс: у парсера и вашего браузера разные cookie. «Продолжить»
помогает, когда ограничение наложено на IP-адрес (типичный случай 429):
после проверки в браузере сайт снимает его с адреса. Если проверка привязана
к cookie, увеличьте паузу (`--delay`, «Бережный» темп), уменьшите глубину и
повторите позже — проверенные карточки уже в кэше.

**«Стоп» в вебе срабатывает примерно за секунду** — даже посреди долгой паузы
после 429: ограничитель просыпается каждые полсекунды.

**Про большие каталоги.** «Весь каталог» крупного бренда — это сотни карточек,
а цена и наличие есть только внутри каждой, поэтому прогон занимает минуты, а
под лимитом и дольше. Интерфейс об этом предупреждает, показывает прогресс,
оценку оставшегося времени и паузы; поиск можно остановить в любой момент, и
найденное останется. Ускоряют дело фильтр по цене и кэш.

## Как устроен парсинг

Сайт отдаёт данные тремя путями:

1. **Страницы каталога** — `/brand/list` и `/brand/<slug>?page=N`; из
   библиотеки доступны и разделы `/category/<slug>` (`Catalog.category_items()`).
   Они рендерятся на сервере, и список товаров лежит прямо в `__NEXT_DATA__`:
   60 товаров на страницу, конец выдачи — неполная страница, предохранитель —
   60 страниц. Бренд задаётся адресом страницы, обувь отбирается по
   `level1CategoryId` (29 — обувь, 1003733 — детская, с `--kids`).
2. **Страница товара** `/product/<slug>-<spuId>` — в её `__NEXT_DATA__`
   лежат цены по каждому размеру, таблица размеров модели и совет по посадке.
   В JSON-ответе карточки (`get-index-spu-detail`) цен у SKU нет вовсе.
3. **JSON API поиска** `/api/v1/h5/home-page/intl/landing/search/page` — им
   пользуются `find` и `search`. Каждый запрос подписывается параметром
   `sign` = md5(отсортированные пары «ключ + значение» + соль); алгоритм
   повторён в `client.calc_sign()`.

Размеры собираются так: `goodsDetail.saleProperties` даёт словарь
`propertyValueId → значение` для каждой шкалы, а `priceInfo.skuInfoList` —
список SKU со ссылкой на `propertyValueId` размера и `minPrice`. Соединение
этих структур и даёт «размер → цена». Прочие свойства SKU (полнота, издание)
становятся «вариантом», а размер считается доступным, если у SKU есть цена и
активный статус.

Фильтры сайта по бренду и размеру через URL не работают: SSR игнорирует
query-параметры, а клиентский эндпоинт фильтрации отдаёт рекомендательную
выдачу без учёта переданных фасетов. Поэтому размер отбирается на нашей
стороне, по карточкам.

## Веб-интерфейс и API

`python main.py web` поднимает локальный сервер на `http.server` из
стандартной библиотеки (`poizon_parser/webapp.py`). Он раздаёт собранный
интерфейс из `frontend/dist` или, если сборки нет, запасную страницу
`web/index.html`. Исходники интерфейса — в `frontend/`: Vite 8, React 19,
TypeScript, Tailwind CSS 4 и TanStack Query.

### Раздел «Поиск»

- **Форма:** бренд с подсказками из списка брендов сайта (бренды с официальной
  сеткой помечены), длина стопы (15–40 см, с подсказкой «Как измерить»),
  размерная сетка, глубина поиска (40 моделей, 120 моделей или весь каталог),
  «Цена до», темп запросов и детская обувь. Переключатель «Только бренды с
  официальной размерной сеткой» оставляет в подсказках бренды, чья таблица
  содержит длину стопы.
- **Живой калькулятор:** пока вы вводите, под формой сразу виден ваш размер в
  выбранном бренде (EU, US, UK, длина стопы, маркировка CM/JP) и у остальных
  официальных брендов — ещё до запуска поиска.
- **Ход поиска:** этап (поиск бренда, сбор каталога, проверка карточек),
  прогресс, оценка оставшегося времени и счётчик найденного. Живой монитор
  показывает, что парсер делает в эту секунду (грузит карточку, берёт из кэша,
  ждёт очередь, пережидает лимит), сколько запросов в работе и «активность
  N с назад» по часам сервера. Индикатор меняет цвет при ожидании и краснеет,
  если ответа нет дольше 20 секунд, — тогда появляется подсказка, что делать.
  В конце выводится причина остановки.
- **Результаты** появляются на лету: фото, ярлык POIZON, посадка, длина стопы
  и CM/JP, «≈ перевод», цена, доставка, детали (артикул, вариант, точность
  перевода) и кнопки «Открыть» и «В итоги». Их можно фильтровать (название,
  цена, «Точный перевод», «До 10 дней») и сортировать (по цене, по скорости
  доставки, в порядке каталога). Выгрузка в CSV и JSON и HTML-отчёт берут
  именно отфильтрованный и отсортированный список. CSV рассчитан на русский
  Excel: разделитель `;`, десятичная запятая, BOM.

Форма и выбранная тема (светлая или тёмная) запоминаются в браузере. Без
сохранённой темы (или с незнакомым значением) страница уже с первого кадра
следует теме системы, а сохранённая глубина, которой нет в списке (40, 120 или
весь каталог), сбрасывается на 40. Когда кнопка под фокусом исчезает (сброс
фильтров, чипы фильтров, закрытое сообщение, «Повторить»), фокус клавиатуры
переходит на ближайший подходящий элемент, а не сбрасывается в начало
страницы.

### Раздел «Итоги»

Кнопка «В итоги» сохраняет позицию вместе с запросом, по которому она
найдена. В «Итогах» видны фото, запрос и время сохранения; позиции можно
убрать по одной или очистить все, а подборку — выгрузить в CSV и JSON. Итоги
хранятся на сервере, личные у каждого браузера, и переживают перезапуск.

### Многопользовательский режим

```bash
python main.py web --host 0.0.0.0
```

Сервер слушает все сетевые интерфейсы: на этом компьютере браузер откроет
`http://127.0.0.1:8765/`, а в консоли появится подсказка открыть
`http://<IP этого компьютера>:8765/` с других устройств.

- При первом заходе браузер получает анонимный идентификатор в cookie
  `poizon_uid` (случайный id, без логина и пароля), и «Итоги» каждого хранятся
  отдельно — в `data/picks/<uid>.json`.
- Поиски изолированы сами по себе (у каждого свой `jobId`), а кэш страниц
  сайта общий: если один уже загрузил каталог бренда, остальным он достанется
  из кэша.
- На весь сервер одновременно работают не больше 4 поисков (идущих или на
  паузе): у каждого свой темп запросов, и без потолка нагрузка на сайт росла
  бы с их числом. Следующий `POST /api/search` получает 429 с объяснением на
  русском.
- Интерфейс опрашивает задачу и в фоновой вкладке, поэтому брошенной она
  становится, только когда страницу закрыли или перезагрузили. Задача, которую 30 минут никто не
  опрашивал (`GET /api/search/<id>`), идёт она или стоит на паузе, отменяет
  себя сама (`stop_reason` начинается с «задача брошена») и уходит в обычную
  очистку.
- Аутентификации нет: кто открыл страницу, тот и пользователь. Не открывайте
  сервер в интернет.
- Изменяющие запросы (POST и DELETE) со страниц других сайтов отклоняются с
  кодом 403 — сервер сверяет заголовок `Origin` с `Host`. Клиенты без
  `Origin` (curl, скрипты) проходят.
- Задачи живут в памяти сервера: хранятся последние 20 завершённых, после
  перезапуска интерфейс сообщит, что задача потеряна, и найденное останется
  на экране.

### JSON API

| Метод и путь | Что делает |
|--------------|------------|
| `GET /api/health` | состояние: число задач (всего и активных), загружен ли список брендов, сколько позиций в итогах у текущего пользователя |
| `GET /api/brands` | бренды сайта с пометкой официальной таблицы (кэш 6 часов) |
| `GET /api/convert?foot=26.5&brand=nike&gender=men` | калькулятор размеров, без обращения к сайту |
| `POST /api/search` | запустить поиск; ответ `{"id": ...}` |
| `GET /api/search/<id>` | снимок задачи |
| `POST /api/search/<id>/pause`, `/continue`, `/cancel` | ручная пауза, продолжение, остановка |
| `GET /api/picks` | итоги текущего пользователя |
| `POST /api/picks` | добавить позицию: `{"match": {...}, "query": {...}}` |
| `DELETE /api/picks`, `DELETE /api/picks/<id>` | очистить итоги или убрать одну позицию |
| `POST /api/report` | собрать HTML-отчёт |
| `GET /result/<папка>/index.html` | открыть готовый отчёт |

**`POST /api/search`** принимает `brand`, `size` (число, можно с запятой),
`scale` (интерфейс всегда шлёт `CM`; передавайте шкалу явно), `gender`
(`men`/`women`), `depth` (число карточек; `0` или пусто — весь каталог), `maxPrice`,
`minPrice`, `pace` (`polite`, `normal`, `fast`) и `kids`. Некорректный ввод —
ответ 400 с текстом ошибки; для `CM` действуют границы 15–40 см. Если уже идут
4 поиска — 429. Размер вне официальной таблицы бренда не перебирает каталог:
задача сразу завершается со `status: "error"` и сообщением, в какую таблицу
размер не входит.

**Снимок задачи** содержит `status` (`running`, `captcha`, `done`,
`cancelled`, `error`), `phase` (`brand`, `collect`, `check`), счётчики
`collected`, `checked`, `total`, `found`, найденные `matches`, хвост `log`,
`activity`, `idle_seconds`, `captcha`, `cooldown_until`, `stats`,
`stop_reason` и `error`.

**Действия с задачей** возвращают `{"ok": true}`, а при отказе — `ok: false`
и текст ошибки на русском: 404, если задачи нет, и 409, если действие сейчас
невозможно (например, поставить на паузу уже завершённый поиск). Так же
отвечает `DELETE /api/picks/<id>`, если позиции уже нет.

**`POST /api/report`** собирает отчёт из результатов задачи:

- предпочтительно — `{"jobId": "...", "keys": [{"spu_id": ..., "sku_id": ...}]}`:
  строки берутся из задачи в порядке ключей, поэтому тело запроса маленькое
  при любом числе результатов. Если задачи уже нет — 404, если часть ключей
  не найдена — 409;
- запасной путь — `{"matches": [...]}` со строками целиком (так интерфейс
  поступает после 404 или 409);
- пустой список `keys` или `matches` — 400: «под фильтры ничего не подошло» не
  подменяется всеми результатами.

Дополнительно можно передать `embed: true` (вшить фото), а также `brand`,
`size`, `scale` и `gender` для шапки отчёта, если задачи уже нет. Ответ:
`{"dir": ..., "file": ..., "view": "/result/<папка>/index.html"}`. JSON-тело
любого запроса ограничено 2 МБ (иначе 413).

## HTML-отчёты

Отчёт — один самодостаточный HTML-файл, который можно переслать кому угодно:
получатель откроет его в браузере и увидит все модели с фото, ценами,
размерами и ссылками на POIZON. В CLI его делает `-f html` (команды `shoes` и
`allbrands`), в вебе — кнопка «HTML-отчёт».

- Каждый прогон получает свою папку: `result/<бренд>-<размер>-<дата>-<время>/index.html`,
  например `result/nike-26-5cm-20261015-143000/index.html`. В части размера
  видна шкала: длина стопы — `nike-26-5cm-…`, миллиметры — `nike-265mm-…`,
  остальные шкалы идут первыми: `nike-eu-42-…`, `nike-us-m-9-…`,
  `nike-us-w-7-…`, `nike-uk-8-…`. При совпадении имени добавляется числовой
  суффикс (`-2`, `-3`). Папка `result/` создаётся в корне проекта; в CLI другую
  базовую папку задаёт `-o`.
- Стили встроены, разметка статична — карточки видны и без JavaScript, а
  небольшой встроенный скрипт даёт сортировку по цене и фильтр по названию.
- Фото по умолчанию грузятся с CDN сайта: файл лёгкий, но картинки видны только
  при интернете. `--embed-images` или переключатель «Фото офлайн» скачивает их
  и вшивает в файл как `data:` URI — тогда отчёт полностью автономен.
  Скачиваются только картинки по `https` с доменов сайта (список доменов
  проверяется и на каждом редиректе), не больше 5 МБ каждая; картинки по
  простому `http` остаются ссылками.
- Названия экранируются, ссылки на товары допускаются только `http(s)`.
  Сервер отдаёт отчёты по `/result/...` с заголовком
  `Content-Security-Policy` с директивой `sandbox`: открытый отчёт живёт в
  изолированном origin и не дотянется до API и cookie приложения.
- Пути `/result/...` и `/assets/...` проверяются лексически ещё до обращения к
  диску: пустой сегмент, `.`, `..`, обратный слеш, `:` или NUL дают 403, а
  UNC-пути не открываются никогда. Символические ссылки, ведущие за пределы
  папки, тоже отклоняются.

Папка `result/` указана в `.gitignore`, её можно смело удалять.

## Использование как библиотеки

Пакета в PyPI нет: импортируйте `poizon_parser` из корня репозитория (или
добавьте его в `PYTHONPATH`).

```python
from poizon_parser import PoizonClient, SizeFinder
from poizon_parser.catalog import Catalog
from poizon_parser.sizechart import sizes_for_foot

# Калькулятор работает без сети
print(sizes_for_foot("adidas", 26.5))
# {'brand': 'Adidas', 'gender': 'men', 'requested_foot': 26.5, 'exact': False,
#  'eu': 43.3333, 'us': 9.5, 'uk': 9.0, 'cm': 27.5, 'foot': 26.7}

client = PoizonClient(delay=1.0, cache_dir=".cache")
finder = SizeFinder(client, on_progress=print)

# Обувь бренда по длине стопы — как команда shoes
for match in finder.find_by_brand("nike", size=26.5, scale="CM", limit=10, workers=3):
    print(match.product.title, match.offer.size_label, match.offer.price)

# Все размеры конкретной модели
product = finder.load_product(8900001978861819)
for offer in product.in_stock_offers():
    print(offer.sizes, offer.variant_label, offer.price, offer.delivery)

# Бренды сайта
for brand in Catalog(client).brands()[:5]:
    print(brand.brand_id, brand.name, brand.slug)
```

- `SizeFinder.find_by_brand()` — основной сценарий; шкала по умолчанию здесь
  `EU`, для длины стопы передайте `scale="CM"`. Границы 15–40 см проверяют CLI и
  веб-сервер, а не библиотека; размер вне официальной таблицы бренда — сразу
  `ValueError`, ещё до сбора каталога.
- `SizeFinder.find_in_official_brands()` — обход всех брендов с официальной
  таблицей (как `allbrands`), `find()` — поиск по названию (как `find`).
- `find()` и `find_in_products()` (проверка конкретных ссылок или spuId)
  сводят шкалу по тому же правилу
  `resolve_query_scale`, что CLI и веб (шкала, написанная в размере, главнее),
  и поднимают `ValueError` для шкал, кроме RU и EU, и при расхождении шкалы в
  размере с переданной.
- Все они возвращают список `Match`: `.product`, `.offer`, `.matched_scale`,
  поля перевода (`converted_eu`, `converted_foot`, `converted_cm`,
  `exact_conversion`, `conversion_note`) и `.to_dict()` для сериализации.
- `PoizonClient` принимает `delay`, `timeout`, `retries`, `cache_dir`,
  `cache_ttl` и колбэки `on_challenge`, `on_cooldown`, `on_activity`.
  `on_challenge(info)` получает словарь с адресом проверки (`url`) и причиной
  (`reason`), **блокируется** до решения пользователя и возвращает `True`
  (повторить запрос) или `False` (прекратить). Без колбэка проверка сразу
  поднимает `ChallengeRequired`. Веб-задача реализует колбэк через
  `threading.Condition` со счётчиком поколений, терминал — через общий для
  всех потоков вопрос.
- В `poizon_parser.sizechart` есть офлайн-функции `sizes_for_foot()`,
  `compare_brands()`, `convert_to_eu()`, `generic_foot_to_eu()` (общая сетка
  стопы), `load_brand_charts()` и `official_charts()`, а у таблицы бренда —
  `BrandChart.published_range()` (диапазон шкалы в таблице).
  `finder.out_of_table_message()` объясняет, почему размер заведомо не
  найдётся у бренда (или возвращает `None`), а
  `client.default_cache_dir()` — путь к папке кэша по умолчанию.

## Разработка

Требования: Python 3.9+ (бэкенд должен оставаться совместимым с 3.9 и только
на стандартной библиотеке), для фронтенда — Node.js 22.13+ или 24+ и pnpm
(версия закреплена в `frontend/package.json`, удобно включить через
`corepack enable`).

### Бэкенд

```bash
python -m unittest discover -s tests       # все тесты
python -m unittest tests.test_cli          # один модуль
python tools/build_size_charts.py --check  # JSON таблиц совпадает с генератором
python tools/build_size_charts.py          # пересобрать JSON после правки таблиц
```

Тесты не обращаются к сайту: сетевые вызовы подменяются, а разбор карточки
проверяется на сохранённой выдаче `tests/fixtures/product_nb530.json`.

### Фронтенд

```bash
cd frontend
pnpm install
pnpm dev            # Vite на http://127.0.0.1:5173/
pnpm typecheck      # tsc --noEmit
pnpm test           # vitest
pnpm build          # typecheck + сборка в frontend/dist
pnpm format         # prettier --write
pnpm format:check   # prettier --check (pnpm-lock.yaml не проверяется)
```

Для разработки запустите API и Vite в двух терминалах:

```bash
# терминал 1 — Python API
python main.py web --no-open

# терминал 2 — интерфейс
cd frontend
pnpm dev
```

Vite проксирует `/api` и `/result` на `http://127.0.0.1:8765`, сохраняя
заголовок `Host`, поэтому проверка `Origin` работает и в dev-режиме.
Production-сборка из `frontend/dist` подхватывается Python-сервером без
копирования файлов.

### CI

Workflow [CI](.github/workflows/ci.yml) на каждый push в `main` и pull request
запускает тесты бэкенда на Python 3.9–3.14 (Ubuntu) и 3.12 (Windows),
`build_size_charts.py --check`, а для фронтенда — `pnpm format:check`,
`pnpm typecheck`, `pnpm test` и `pnpm build` на Node.js 22.

## Ограничения

- Перевод размера точен, только когда значение есть в официальной таблице
  бренда или товара. Всё остальное — ближайшая строка или общая сетка с
  пометкой «≈»; если знаете свой размер в EU, укажите его.
- Официальные таблицы — ручной снимок с датой сверки; производители иногда
  меняют свои сетки.
- Цена и наличие есть только в карточке товара, поэтому каждая модель
  загружается отдельно. «Весь каталог» крупного бренда — это сотни карточек и
  от нескольких минут до десятков минут; повторный прогон ускоряет кэш.
- Разбор опирается на структуру `__NEXT_DATA__` и подпись поискового API; при
  изменениях на сайте их придётся обновить (`extract.py`, `catalog.py`,
  `client.py`).
- Цены и наличие меняются постоянно — результат актуален на момент запуска.
  Итоговая сумма при оформлении заказа на сайте может отличаться от цены в
  карточке.
- Парсер только читает публичные страницы: авторизации, корзины и оформления
  заказа здесь нет, капчи он не решает.
- У веб-сервера нет аутентификации — запускайте его только у себя или в
  доверенной локальной сети.
